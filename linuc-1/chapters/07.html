07 パッケージ管理

ソフトウェアの導入・更新・調査はパッケージマネージャが中心です。Debian 系（apt / dpkg）と RPM 系（dnf/yum / rpm）の両方を、リポジトリの感覚付きで使えるようにします。

1. リポジトリの考え方

パッケージは単体ファイルだけでなく、リポジトリ（配布元の索引）から依存関係ごと入れるのが現代の基本です。

系 高水準 低水準 設定の目安
Debian 系 apt / apt-get dpkg /etc/apt/sources.list など
RPM 系 dnf / yum rpm /etc/yum.repos.d/

高水準が依存解決、低水準が個別 .deb / .rpm の操作、と覚えると迷いにくいです。

2. Debian 系（apt / dpkg）

sudo apt update
sudo apt install nginx
sudo apt remove nginx
sudo apt purge nginx          # 設定も消す寄り
sudo apt upgrade
apt search keyword
apt show nginx
apt-cache policy nginx
apt-file search bin/nginx     # 環境により apt-file 要導入

sources.list / sources.list.d/ で配布元を管理します。間違った第三リポジトリは供給チェーンリスクになるため、追加は理由を残します。

dpkg:

sudo dpkg -i package.deb
dpkg -l
dpkg -L nginx                 # 導入済みパッケージのファイル一覧
dpkg -S /usr/sbin/nginx       # ファイルの所有者パッケージ
sudo dpkg-reconfigure package

依存が欠けて dpkg -i が失敗したら、apt -f install で修復する流れが典型です。

3. RPM 系（dnf / yum / rpm）

現行の RHEL 系クローンでは dnf が主流です。Version 10.0 の文言は yum 中心、11.0 でも RPM 系操作は残ります。現場では dnf を主、yum は互換コマンドとして触れます（「11.0で特に重視」＝現行ツール）。

sudo dnf install nginx
sudo dnf remove nginx
sudo dnf update
dnf search keyword
dnf info nginx
dnf provides /usr/sbin/nginx

リポジトリ定義は /etc/yum.repos.d/*.repo。enabled=0/1 や baseurl / metalink を確認します。

rpm（低水準）:

sudo rpm -ivh package.rpm
rpm -qa
rpm -ql nginx
rpm -qf /usr/sbin/nginx
rpm -qi nginx
rpm -V nginx                  # 改ざん・変更の検証寄り

署名や依存の詳細は rpm で調べ、導入は可能なら dnf に任せるのが安全です。

4. 調査の定番質問

知りたいこと Debian 系 RPM 系
入っているか dpkg -l / apt list --installed rpm -qa / dnf list installed
ファイルは誰の？ dpkg -S rpm -qf / dnf provides
パッケージの中身 dpkg -L rpm -ql
情報・依存 apt show dnf info

5. 更新と本番の注意

  • 本番は変更窓・バックアップ・ロールバック手段を先に
  • upgrade / update 前に何が上がるか確認
  • カーネル更新後は再起動が必要なことが多い
  • 自動更新を入れるなら、再起動ポリシーと監視をセットで

6. 現場チェック

  • [ ] apt update と install / remove ができる
  • [ ] dpkg -S / dpkg -L でファイルとパッケージを相互に辿れる
  • [ ] dnf install と dnf provides ができる
  • [ ] rpm -qf / rpm -ql の意味を説明できる
  • [ ] リポジトリ設定ファイルの場所を両系で言える

手元に AlmaLinux と Debian/Ubuntu のどちらか一方しか無くても、もう一方はコマンド対応表で追えます。可能なら両方のコンテナや VM で一度ずつ打ってください。
