04 ファイルと権限 FHS

Linux 管理の大半は「どのパスに何があり、誰が読めるか」の把握です。この章では FHS の見方、権限ビット、所有者、リンク、検索を実務の操作単位で押さえます。

1. パスと FHS の見方

絶対パスは / から、相対パスはカレントからの位置です。FHS（Filesystem Hierarchy Standard）は、重要なディレクトリの役割を共通化する取り決めです。細かい個別ファイル名の暗記より、「何を置く場所か」を説明できることが目標です。

パス（例） 役割のイメージ
/ ルート。全体の起点
/etc ホスト固有の設定
/var 可変データ（ログ、スプールなど）
/home 一般ユーザのホーム
/usr 共有のプログラムやデータ
/tmp 一時ファイル
/proc /sys カーネル／実行中の情報が見える仮想 FS

Version 10.0 / 11.0 ともに「重要な位置と目的を知っている」ことが求められます。現場でも「ログは /var/log、設定は /etc」と indirection なく辿れるかが速度に直結します。

pwd
cd /var/log
ls -la

2. 権限の読み方（ls -l）

-rw-r--r-- 1 alice develop 1200 Nov 17 10:00 report.txt
drwxr-xr-x 2 alice develop 4096 Nov 17 10:00 docs

左端の 10 文字:

  1. 種別（- 通常、d ディレクトリ、l シンボリックリンク など）
    2〜4. 所有者（user）の rwx
    5〜7. グループ（group）の rwx
    8〜10. その他（others）の rwx
記号 ファイル ディレクトリ
r 読み取り 一覧（エントリ名）
w 書き込み 作成・削除・改名（中身の変更に関わる）
x 実行 そのディレクトリへ cd して中を辿る

数値モード（例）:

値 意味
7 rwx
6 rw-
5 r-x
4 r--
0 --- 
chmod 644 report.txt
chmod u+x script.sh
chmod go-w secret.conf

ディレクトリに入れるが一覧できない、一覧できるが中のファイルに辿れない、といった症状は r と x の組み合わせで説明できます。

3. 所有者とグループ

ls -l
chown alice report.txt
chown alice:develop report.txt
chgrp develop report.txt
  • ファイルの「誰のものか」はアクセス制御の第一関門です。
  • サービス用ディレクトリは、実行ユーザに必要最小限だけ渡すのが安全側です。
  • chmod / chown / chgrp は破壊的になり得るので、本番では対象パスを再確認してから実行します。

特殊ビット（概要だけ）:

  • setuid / setgid: 実行時の実効ユーザ／グループに影響
  • sticky（例: /tmp）: ディレクトリ内で、他人のファイルを消せなくする

詳細な監査や sudo 委譲は第09章で扱います。ここでは「ビットがおかしいとサービスが読めない／書き込めない」と結び付けてください。

4. ハードリンクとシンボリックリンク

ln original.txt hardlink.txt      # ハードリンク
ln -s /etc/hosts hosts.link       # シンボリックリンク
ls -li                            # inode を見る
ハードリンク シンボリックリンク
実体 同じ inode を共有 パス名を指す別エントリ
跨ぎ 通常は同一ファイルシステム 別 FS やディレクトリも可
見た目 通常ファイルと同じ l で表示、-> 先を示す

識別の要点:

  • ls -i で inode が同じならハードリンクの可能性が高い
  • ls -l で l とリンク先が見えればシンボリックリンク
  • シンボリックの参照先を消すと「壊れたリンク」になる

5. 検索（find / 名前探し）

find /var/log -name '*.log'
find /home -type f -user alice
find /etc -type f -mtime -1
find /tmp -type f -size +10M
オプション例 意味
-name ファイル名（シェルグロブ）
-type f/d/l 通常／ディレクトリ／シンボリック
-user / -group 所有者／グループ
-mtime 更新日からの日数

名前だけなら find のほか、locate 系（DB 依存）もありますが、権限と最新性が必要な調査では find が確実です。大きな木を root から無制限に走査すると負荷と時間に注意します。

6. 現場チェック

  • [ ] /etc /var /home /usr /tmp の役割を一言で言える
  • [ ] ls -l の権限ビットを user/group/other に分解できる
  • [ ] chmod の記号モードと数値モードを両方使える
  • [ ] ハードリンクとシンボリックリンクの違いを inode で説明できる
  • [ ] find で名前・所有者・種別を絞り込める

手を動かす例:

mkdir -p ~/lab04/docs
echo hello > ~/lab04/a.txt
chmod 640 ~/lab04/a.txt
ln ~/lab04/a.txt ~/lab04/a-hard.txt
ln -s ~/lab04/a.txt ~/lab04/a-sym.txt
ls -li ~/lab04
find ~/lab04 -type l
