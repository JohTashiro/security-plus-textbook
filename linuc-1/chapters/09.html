09 ユーザーとセキュリティ

「誰がログインでき、何を昇格でき、どこから入るか」が崩れると、権限のある侵害になります。この章ではアカウント管理、パスワード方針、sudo、SSH 基礎、不要サービスの抑制を実務単位で押さえます。

1. ユーザとグループ

ファイル 役割
/etc/passwd アカウント本体（UID、ホーム、シェル）
/etc/shadow パスワードハッシュと期限（root のみ読める想定）
/etc/group グループ
/etc/gshadow グループの秘匿情報（環境による） 
sudo useradd -m -s /bin/bash alice
sudo passwd alice
sudo usermod -aG wheel alice      # 配布により sudo グループ名は sudo
sudo groupadd developers
id alice
getent passwd alice

新規ユーザの雛形は /etc/skel。デフォルトは /etc/default/useradd や login.defs も関係します。

削除・ロック:

sudo usermod -L alice             # ロック
sudo usermod -U alice             # 解除
sudo userdel -r alice             # ホームも削除（慎重に）

2. パスワードとログイン制御

sudo chage -l alice
sudo chage -M 90 -W 7 alice       # 最大日数・警告
sudo passwd -l alice              # ロック寄り

自動ログアウトは TMOUT（シェル）や PAM／ディスプレイマネージャ設定など手段が複数あります。方針として「放置セッションを残さない」が重要です。

ログイン状況:

who
w
last
lastb                            # 失敗（権限・環境による）

3. sudo による権限委譲

root パスワード共有より、個人アカウント + sudo が監査しやすいです。

sudo -l
sudo visudo                       # /etc/sudoers を安全に編集

/etc/sudoers.d/ に断片を置く運用が主流です。

alice ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx

「全員に NOPASSWD: ALL」は便利ですが事故と侵害の両面で危険です。必要最小限にします。

4. SSH 基礎

ssh alice@192.0.2.10
ssh -i ~/.ssh/id_ed25519 alice@host

鍵認証の定番ファイル:

パス 意味
~/.ssh/id_ed25519（または id_rsa） 秘密鍵
~/.ssh/id_ed25519.pub 公開鍵
~/.ssh/authorized_keys サーバ側の許可公開鍵
~/.ssh/known_hosts 接続先ホスト鍵の記憶 
ssh-keygen -t ed25519 -C "alice@laptop"
ssh-copy-id alice@host

サーバ側 /etc/ssh/sshd_config の要点例:

  • PasswordAuthentication no（鍵のみにする場合）
  • PermitRootLogin no（または prohibit-password）
  • Port 変更は隠蔽であり本質対策ではない

切断は exit / logout / Ctrl+D。

5. ホスト／ネットワークサービスの保護

攻撃面を減らす基本:

  1. 使っていないサービスを止める・無効化する
  2. ファイアウォールで必要ポートだけ開ける（詳細は第10章）
  3. パッケージと SSH を最新寄りに保つ
systemctl list-units --type=service --state=running
sudo systemctl disable --now cups    # 例: 不要なら

Version 10.0 は iptables / firewalld の概要、11.0 は firewalld と ufw の操作 が中心です（次章で手順化）。

6. 現場チェック

  • [ ] useradd / passwd / usermod -aG ができる
  • [ ] passwd / shadow / group の役割を説明できる
  • [ ] chage で期限を確認・設定できる
  • [ ] visudo の意味と最小権限の例を言える
  • [ ] 鍵を作り authorized_keys で入れる流れを説明できる
  • [ ] 不要サービスを systemctl で止められる

手元 VM で一般ユーザを作り、鍵 SSH → sudo で限定コマンド、まで通してください。
