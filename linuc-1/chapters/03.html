03 シェルとコマンドライン

Linux 管理の中心はシェルです。パイプとリダイレクトが手に馴染むと、調査・一括処理・自動化の速度が一気に上がります。この章では対話操作、入出力、ジョブ制御、tmux を扱います。

1. シェルとは

シェルはユーザの入力を解釈し、コマンドを起動するプログラムです。ログインシェルの定番は bash（環境により zsh など）。スクリプトも同じ文法で書けます（本格は第12章）。

echo $SHELL
bash --version

2. パスと移動・確認

pwd                 # 現在地
cd /var/log
cd ~                # ホーム
cd -                # 直前のディレクトリ
ls -la
which systemctl     # コマンドの実体パス
type ls             # エイリアスか外部コマンドか

絶対パス（/ から）と相対パス（. / ..）を混同しないこと。権限エラーは「存在しない」のか「許可がない」のかを切り分けます。

3. リダイレクトとパイプ

記法 意味
> 標準出力を上書き保存
>> 標準出力を追記
2> 標準エラーをリダイレクト
2>&1 エラーを出力と同じ行き先へ
< ファイルを標準入力へ
\| 左の出力を右の入力へ

例:

ls /etc > /tmp/etc-list.txt
command_that_fails 2> /tmp/err.txt
journalctl -u ssh | less
grep -i error /var/log/syslog | tail -n 20

調査では「絞る → 見る」をパイプでつなぐのが基本です。巨大出力をそのまま端末に流さない。

4. クォートと展開

  • ダブルクォート: 変数展開する（"$HOME"）
  • シングルクォート: ほぼ展開しない
  • スペースを含む引数は必ずクォートする
NAME="Alice"
echo "Hello $NAME"
echo 'Hello $NAME'    # 文字どおり $NAME

5. ジョブ制御と nohup

操作 意味
Ctrl+C 割り込み（終了シグナル）
Ctrl+Z サスペンド
jobs ジョブ一覧
bg / fg バックグラウンド／フォアグラウンド
command & 最初からバックグラウンド 
long_task &
nohup ./batch.sh > /tmp/batch.out 2>&1 &

nohup はログアウト後も継続させたいときに使います。Version 11.0 では screen より tmux / nohup 側が中心です。

6. tmux（端末マルチプレクサ）

長時間作業や複数ペインでの監視に使います。

tmux                  # 新規セッション
Ctrl+b → d            # デタッチ（切り離し）
tmux attach           # 再接続
Ctrl+b → % または "   # ペイン分割（設定による）

SSH が切れてもセッションを残せるのが最大の利点です。本番作業の定石です。

7. 履歴と効率化

history
Ctrl+R                # 履歴検索
!!                    # 直前コマンド

危険コマンドの再実行は確認してから。rm やリダイレクト先は特に慎重に。

8. 現場チェック

  • [ ] > と >> と 2> の違いを説明できる
  • [ ] cmd1 | cmd2 | cmd3 で調査できる
  • [ ] Ctrl+Z / bg / fg を使える
  • [ ] tmux でデタッチ／アタッチできる
  • [ ] スペース入りパスをクォートできる
