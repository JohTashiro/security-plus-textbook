11 サービスとログ

サービスが「今動いているか」、異常時に「何が起きたか」、相関のために「時刻が合っているか」が運用の三本柱です。この章では systemd ユニット操作、journal / rsyslog、ログローテ、時刻同期を実務単位で押さえます。

1. systemd でサービスを扱う

第02章の続きとして、日常運用コマンドを固めます。

systemctl status nginx
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx          # 対応サービスのみ
sudo systemctl enable nginx          # 起動時有効
sudo systemctl disable nginx
systemctl is-active nginx
systemctl is-enabled nginx

ユニットファイルの場所の感覚:

場所 意味
/lib/systemd/system/ または /usr/lib/systemd/system/ パッケージ配布
/etc/systemd/system/ 管理者が優先して置く 
systemctl cat nginx
sudo systemctl daemon-reload         # ユニット変更後

タイマー（11.0で特に重視）

cron に加え、systemd timer が現行の定番になりつつあります。

systemctl list-timers --all
systemctl status logrotate.timer
ペア 役割
.timer いつ起動するか
.service 何を実行するか

Version 10.0 の cron（crontab、/etc/cron.*）も現場では残るため、両方の存在を知っておきます。主手順は timer と journal 連携を優先してよいです。

2. journal（journalctl）

journalctl -xe
journalctl -u nginx
journalctl -u nginx --since "1 hour ago"
journalctl -f
journalctl -p err
journalctl -b                          # 今回のブート

永続化は /var/log/journal/ の有無や journald.conf の Storage= に依存します。ディスクを圧迫したら保持期間やサイズ上限を設計します。

3. rsyslog と従来ログ

多くの配布で /var/log/syslog や /var/log/messages、アプリ別ファイルが残ります。

sudo tail -f /var/log/syslog
ls /var/log

中央集約のイメージ:

  • クライアント: リモートへ転送
  • サーバ: 受信を許可し保管

詳細なテンプレート暗記より、「どこに・何が・どの facility/severity で出るか」を追えることが先です。

4. ログローテーション

ls /etc/logrotate.d/
sudo logrotate -d /etc/logrotate.conf    # ドライラン

ローテ・圧縮・削除を自動化し、ディスク満杯を防ぎます。アプリがファイルハンドルを握ったままなら postrotate で再オープンが必要、という感覚を持ってください。

5. 時刻同期

時刻ずれはログ相関・証明書・Kerberos 等を壊します。

系 現行寄り
chrony RHEL 系などで主流
systemd-timesyncd 軽量クライアント寄り 
chronyc tracking
chronyc sources -v
timedatectl
timedatectl show-timesync

設定例の場所: /etc/chrony.conf または /etc/chrony/chrony.conf。

Version 10.0 にあった ntpd / ntpdate は 11.0 草案では薄まり、chrony と timesyncd が中心です（「11.0で特に重視」）。比較として「昔は ntpd もあった」程度で十分です。

timedatectl set-timezone Asia/Tokyo

6. 現場チェック

  • [ ] start/stop/enable/status を迷わず打てる
  • [ ] journalctl -u と --since で追える
  • [ ] /var/log と journal の役割分担を説明できる
  • [ ] logrotate の存在と目的を言える
  • [ ] timedatectl / chronyc で同期状態を確認できる
  • [ ] timer と service のペアを説明できる

手元で nginx や sshd の journal を追い、わざと設定ミス → ログで原因、を一度体験してください。
