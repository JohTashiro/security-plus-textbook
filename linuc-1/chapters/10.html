10 ネットワーク設定

アドレス・経路・名前解決・ファイアウォールが揃って初めて「届く」状態になります。この章では ip、NetworkManager、Netplan、DNS、firewalld/ufw、切り分け手順を実務単位で押さえます。

1. TCP/IP の現場メモ

要素 押さえること
IPv4 アドレス、マスク／CIDR、ゲートウェイ
IPv6 リンクローカルとグローバルの感覚
ポート 22/ssh、80/http、443/https、53/dns など
名前解決 DNS と /etc/hosts

詳細なサブネット計算は CCNA 寄りでも、Linux 側では「この NIC の CIDR と default route」を即座に読めることが重要です。

2. ip コマンド（現行の基本）

ip link
ip -br addr
ip addr show eth0
sudo ip addr add 192.0.2.10/24 dev eth0
sudo ip link set eth0 up
ip route
sudo ip route add default via 192.0.2.1

一時設定は再起動で消えることが多いです。永続化は配布の仕組みに任せます。

旧 ifconfig / route は 10.0 文脈ではまだ見えますが、現場と 11.0 は ip 中心です（「11.0で特に重視」）。

3. NetworkManager と Netplan / ifupdown

系 典型 操作
RHEL 系など NetworkManager nmcli / nmtui
Ubuntu 系 Netplan → 裏で NM 等 /etc/netplan/*.yaml + netplan apply
古い Debian 系 ifupdown /etc/network/interfaces 
nmcli device status
nmcli connection show
sudo nmcli connection modify eth0 ipv4.addresses 192.0.2.10/24
sudo nmcli connection modify eth0 ipv4.gateway 192.0.2.1
sudo nmcli connection modify eth0 ipv4.dns "192.0.2.53"
sudo nmcli connection modify eth0 ipv4.method manual
sudo nmcli connection up eth0

Netplan 例（概念）:

network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses: [192.0.2.10/24]
      routes:
        - to: default
          via: 192.0.2.1
      nameservers:
        addresses: [192.0.2.53]

sudo netplan try
sudo netplan apply

Version 11.0 で Netplan が明示（「11.0で特に重視」）。無線は nmcli や iw でリンク状態を見る、程度で足場になります。

4. DNS と名前解決

resolvectl status          # systemd-resolved 環境
cat /etc/resolv.conf
getent hosts example.com
ping -c 3 example.com

/etc/hosts はローカル上書き。切り分けでは「名前は解けるが IP に届かない」と「名前が解けない」を分離します。

5. ファイアウォール（firewalld / ufw）

配布寄り ツール
RHEL 系 firewalld / firewall-cmd
Ubuntu 系 ufw 
sudo firewall-cmd --state
sudo firewall-cmd --get-default-zone
sudo firewall-cmd --list-all
sudo firewall-cmd --add-service=http --permanent
sudo firewall-cmd --add-port=8080/tcp --permanent
sudo firewall-cmd --reload

sudo ufw status
sudo ufw allow 22/tcp
sudo ufw allow 'Nginx Full'
sudo ufw enable

Version 10.0 の iptables「概要」は、現行主流（firewalld/ufw）への橋渡しとして短く触れれば十分です。11.0 は操作そのものが範囲です（「11.0で特に重視」）。

6. 切り分けの定石

  1. リンク UP か（ip link）
  2. アドレスとマスクか（ip addr）
  3. デフォルト経路か（ip route）
  4. 同網・GW へ ping
  5. 名前解決か（getent / resolvectl）
  6. 待ち受けと FW か（ss -tlnp、firewall）
ping -c 3 192.0.2.1
traceroute 192.0.2.1      # または tracepath
ss -tlnp
ip neigh

7. 現場チェック

  • [ ] ip addr / ip route で現状を読める
  • [ ] nmcli または Netplan で静的 IP を永続化できる
  • [ ] DNS 障害と到達性障害を切り分けられる
  • [ ] firewalld または ufw でサービス／ポートを許可し永続化できる
  • [ ] ss -tlnp で待ち受けを確認できる

手元 VM で静的 IP → 再起動後も維持 → HTTP 用ポート許可、まで一度通してください。
