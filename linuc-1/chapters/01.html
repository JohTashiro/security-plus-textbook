01 システムとハードウェア

Linux を安定運用するには、「今見ているマシンがどんなハードウェア／仮想環境か」を素早く把握できることが前提です。この章ではアーキテクチャの見方、デバイスの考え方、BIOS/UEFI、情報収集コマンド、仮想化の見分けを扱います。

1. アーキテクチャを読む

サーバや PC は、CPU・メモリ・バス・ストレージ・NIC が組み合わさった箱です。障害時はアプリより先に「CPU 飽和か、メモリ不足か、ディスク待ちか、NIC か」を切り分けます。

確認の入口:

uname -m          # 例: x86_64, aarch64
lscpu             # CPU ソケット/コア/スレッド、仮想化フラグなど
free -h           # メモリとスワップ

lscpu の Virtualization やフラグ（vmx / svm など）は、そのホストで KVM 等が使えるかの手がかりになります。

2. デバイスファイルの考え方

Linux はハードウェアをファイルとして扱います。ブロックデバイスは /dev/sda や /dev/nvme0n1、パーティションは /dev/sda1 のように見えます。キャラクタデバイスは端末や一部の周辺機器です。

lsblk             # ディスクとパーティションの木構造
ls -l /dev/disk/by-uuid

「どのディスクがルートか」「追加した SSD はどの名前か」は、作業前に必ず lsblk で確認します。破壊的な mkfs や dd は対象デバイスを取り違えると致命傷です。

3. BIOS / UEFI とブートの入口

  • BIOS（レガシー）: 古いブート方式。MBR とセットで語られることが多い。
  • UEFI: 現行の主流。GPT と組み合わせ、セキュアブートなどを扱える。

OS に入った後でファーム設定そのものは触れませんが、「起動しない」ときはファームのブート順・セキュアブート・仮想化支援（Intel VT-x / AMD-V）を疑います。ブートローダや systemd の詳細は第02章です。

4. ハードウェア情報コマンド

コマンド 見ること
lscpu CPU・アーキテクチャ・仮想化
lspci PCI デバイス（NIC、GPU、ストレージコントローラ）
lsusb USB デバイス
lsblk ブロックデバイス
dmidecode SMBIOS 情報（権限が必要なことが多い）
ip link / nmcli device NIC の有無と状態（詳細は第10章）

例:

lspci | grep -i ether
lsusb
lsblk -f

「NIC が増えない」「ディスクが見えない」ときは、まず OS がデバイスを認識しているかをここで確認します。

5. 仮想化の見分け

ホスト型とハイパーバイザー型

  • ホスト型: 通常のホスト OS の上に仮想化ソフトを載せる（例: VirtualBox をデスクトップに入れるイメージ）。
  • ハイパーバイザー型（ベアメタルに近い）: 仮想化層が中心で、その上にゲストを載せる（KVM や多くのサーバ仮想化）。

現場では厳密な分類より、「今ログインしているのは物理か、ゲストか」「ネストした仮想化か」が重要です。

実機か仮想か

systemd-detect-virt
# 例: kvm, oracle, microsoft, vmware, none

none なら（検出上は）物理に近い環境です。ゲストでは一部デバイスが仮想化され、時刻ずれや NIC 名の違いが出やすくなります。

KVM / VirtualBox / Xen / コンテナ

  • KVM: Linux カーネルの仮想化。サーバ仮想化の定番候補。
  • VirtualBox: デスクトップ検証でよく使う。
  • Xen: 別系統のハイパーバイザー。
  • コンテナ（Docker など）: カーネルを共有する軽量隔離。docker container ls や docker run は第13章で扱う。ここでは「VM より軽く、アプリ配布に使う」と理解すれば十分。

Version 11.0 では、仮想化の説明が virsh 操作中心から、ホスト型／ハイパーバイザー型や systemd-detect-virt・lscpu・コンテナ基本へと寄っています。現行主流の見分け方を優先して覚えてください。

6. 電源・ACPI の実務メモ

ノート PC や一部サーバでは ACPI 経由で電源状態を扱います。リモートで落ちない・サスペンドする、といった症状は電源管理ポリシーも疑います。サーバ用途ではまず「突然の電源断がないか」「BMC/iLO 等の遠隔管理はあるか」を確認するのが先です。

7. 現場チェック

  • [ ] lscpu / lsblk / lspci で自分の環境の概要を説明できる
  • [ ] systemd-detect-virt の結果を解釈できる
  • [ ] VM とコンテナの違いを隔離の単位で説明できる
