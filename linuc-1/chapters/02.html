02 起動とランレベル systemd

電源投入からログインプロンプトが出るまで、Linux はブートローダ → カーネル → init（現在はほぼ systemd）の順で進みます。この章では起動の流れと、サービスの開始／停止／自動起動、タイマーを実務目線で押さえます。

1. 起動の流れ（概要）

  1. ファームウェア（BIOS/UEFI） がディスクやネットワークからブートローダを探す
  2. ブートローダ（GRUB など） がカーネルと initramfs を読み込む
  3. カーネル がハードウェアを初期化し、ルートファイルシステムをマウントする
  4. systemd（PID 1） がターゲットに従ってサービスを起動する

「起動しない」ときは、どの段階で止まったか（ファームのブートメニューか、GRUB か、emergency shell か）を切り分けるのが先です。

2. GRUB の実務ポイント

  • 設定の実体はディストリにより grub.cfg の生成元が違う（Debian 系は /etc/default/grub など）。
  • カーネルパラメータ（例: systemd.unit=rescue.target）でレスキュー起動できる。
  • 安易な直接編集より、配布の更新手順（update-grub / grub2-mkconfig）に従う。

詳細なカスタムは現場の手順書に合わせ、ここでは「カーネル選択とレスキュー起動ができる」ことを目標にします。

3. systemd の基本単位

種類 拡張子 役割
サービス .service デーモンやワンショット処理
ターゲット .target 到達したい状態のまとまり（旧ランレベルの相当）
タイマー .timer 時間起動（cron の代替・併用）
ソケット .socket 待ち受け連動起動
マウント .mount マウント操作

よく使うターゲット:

  • multi-user.target … コンソールの通常マルチユーザ（旧 runlevel 3 相当のイメージ）
  • graphical.target … GUI 付き
  • rescue.target / emergency.target … 修復用
systemctl get-default
systemctl set-default multi-user.target   # 変更は慎重に
systemctl list-units --type=target

4. サービスの操作

systemctl status sshd          # または ssh（ディストリ差）
systemctl start nginx
systemctl stop nginx
systemctl restart nginx
systemctl reload nginx         # 対応サービスのみ
systemctl enable nginx         # ブート時自動起動
systemctl disable nginx
systemctl is-enabled nginx
systemctl is-active nginx

ログは journalctl -u サービス名 が第一候補です（詳細は第11章）。

失敗したら:

systemctl status サービス名 -l
journalctl -u サービス名 -e

依存関係で起動できないこともあるので、systemctl list-dependencies も有用です。

5. タイマー（systemd timer）

Version 11.0 で特に重視される項目です。cron だけに頼らず、.timer と .service のペアで定期実行できます。

systemctl list-timers --all
systemctl status logrotate.timer   # 例（環境による）

ポイント:

  • OnCalendar= でカレンダー起動、OnBootSec= などで相対起動
  • 実処理は対応する .service 側
  • 失敗時の再試行やジャーナル連携がしやすい

従来の cron（crontab -e、/etc/cron.*）もまだ広く使われます。両方の存在を知ったうえで、新規は timer を検討できるとよいです。

6. 旧 SysV / chkconfig との関係

古い資料や一部環境では service コマンドや chkconfig、init.d スクリプトが残ります。現行主流は systemd です。互換レイヤ経由で動いていることも多いので、トラブル時は「実体の unit は何か」を systemctl status で確認します。

7. 現場チェック

  • [ ] 起動の4段階（ファーム→ブートローダ→カーネル→systemd）を説明できる
  • [ ] systemctl enable/start/status を使い分けられる
  • [ ] デフォルトターゲットの意味が分かる
  • [ ] systemctl list-timers で定期実行を確認できる
