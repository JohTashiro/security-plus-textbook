12 シェルスクリプト

同じ手順を何度も打つなら、スクリプトにして再現性とレビュー可能性を上げます。この章では shebang、変数、引用、分岐、ループ、終了コード、実務で壊れにくい書き方を押さえます。

1. 基本形

#!/bin/bash
set -euo pipefail

echo "hello"
要素 意味
shebang どのインタプリタで動かすか
set -e 失敗で止める（例外あり）
set -u 未定義変数をエラーに
set -o pipefail パイプ途中失敗も拾う 
chmod +x backup.sh
./backup.sh
bash backup.sh

2. 変数と引用

name="alice"
echo "$name"
echo "${name}_home"
書き方 効果
"$var" 空白を保持しつつ展開
'$var' 展開しない
$var 単語分割や glob の罠が起きやすい

位置パラメータ:

#!/bin/bash
# usage: ./greet.sh Alice
user=${1:?need name}
echo "hello, $user"
変数 意味
$0 スクリプト名
$1… 引数
$# 引数個数
"$@" 全引数（安全に渡す定番）

3. 分岐と終了コード

if [[ -f /etc/os-release ]]; then
  echo "found"
elif [[ -d /etc ]]; then
  echo "etc only"
else
  echo "missing"
  exit 1
fi
終了コード 慣習
0 成功
非0 失敗 
command -v curl >/dev/null || { echo "curl missing"; exit 1; }

条件の定番:

式 意味
-f / -d / -e ファイル／ディレクトリ／存在
-z / -n 空／非空文字列
== / != 文字列比較（[[ ]] 内）
-eq 等 整数比較

4. ループ

for f in /var/log/*.log; do
  [[ -e $f ]] || continue
  echo "file=$f"
done

while read -r line; do
  echo "got:$line"
done < /etc/hosts

無限ループと sleep で監視風にする例もありますが、本番は systemd timer や監視ツールと役割分担します。

5. 関数とデバッグ

log() {
  echo "[INFO] $*" >&2
}

log "start"

bash -x script.sh              # 実行トレース
bash -n script.sh              # 構文チェック

Version 10.0 / 11.0 ともシェルスクリプトの重要度は高いです。試験は短めの記述・選択が中心なので、引用・終了コード・[[ ]]・for/while を確実にします。

6. 実務パターン（壊れにくい書き方）

#!/bin/bash
set -euo pipefail

src=${1:?usage: $0 SRC DEST}
dest=${2:?usage: $0 SRC DEST}

mkdir -p "$dest"
rsync -a --delete "$src"/ "$dest"/

注意:

  • パスは常に引用
  • 一時ファイルは mktemp
  • 秘密情報をスクリプトに直書きしない
  • root 必要なら最初にチェックし、必要最小限だけ昇格

環境カスタム（~/.bashrc、PATH、alias）は第03章の延長です。スクリプトでは alias に頼らず、フルパスや command で明示すると再現性が上がります。

7. 現場チェック

  • [ ] shebang 付き実行ビットのスクリプトを作れる
  • [ ] "$var" と $@ の理由を説明できる
  • [ ] if / for / while read が書ける
  • [ ] bash -n と bash -x を使える
  • [ ] 引数不足で使い方を出して終了できる

手元で「指定ディレクトリのディスク使用量を報告する」スクリプトを1本書いてください。
