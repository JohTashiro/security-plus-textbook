13 仮想化とコンテナ入門

一台の物理資源を分けて使う代表手段が仮想マシンとコンテナです。この章では方式の違い、KVM／ホスト型の概要、docker の基本操作、見分けコマンドを実務単位で押さえます。

1. なぜ仮想化／コンテナか

目的 例
隔離 障害・権限の影響範囲を限定
密度 1台のハードを複数用途に
再現 同じ環境を作り直せる
移行 オンプレとクラウドの往復

パブリッククラウドでは、インスタンス停止で消える 揮発性ストレージ と、永続ディスクを区別する感覚が重要です（再起動・メンテナンスで消える／残る）。

2. ホスト型とハイパーバイザー型

方式 イメージ 例
ホスト型 通常の OS 上に仮想化ソフト VirtualBox など
ハイパーバイザー型 ハイパーバイザーが VM を直接制御 KVM、Xen など

ハードウェア仮想化支援（Intel VT-x / AMD-V）の有無が性能と可否に効きます。

lscpu | grep -i virtualization
systemd-detect-virt

systemd-detect-virt は「今の OS が VM／コンテナの中か」を見るのに便利です（Version 11.0 で明示、「11.0で特に重視」）。

3. 仮想マシンとコンテナの違い

観点 仮想マシン コンテナ
カーネル ゲストごとに持つ ホストカーネルを共有
起動 重い〜中 軽い
隔離 強め プロセス／namespace 中心
向く用途 別 OS、強い隔離 アプリ配布、密度

コンテナは「軽い VM」ではなく、プロセス隔離＋ファイルシステム層に近い、と説明できると現場で誤解が減ります。

4. KVM / virsh（概要）

Linux では KVM がカーネル内の仮想化、QEMU がエミュレーション／デバイス、libvirt（virsh）が管理、という分担が多いです。

Version 10.0 は virsh での起動停止が列挙されます。11.0 草案は方式名と docker／検知コマンド寄りで、virsh 操作の比重は下がります。両方を知ったうえで、手元に libvirt があれば触ってください。

virsh list --all
virsh start vm01
virsh shutdown vm01
virsh console vm01

5. Docker 基本操作

docker version
docker image ls
docker container ls -a
docker container run --rm -it alpine:latest sh
docker container run -d --name web -p 8080:80 nginx:alpine
docker container logs web
docker container stop web
docker container rm web

Version 11.0 は docker container run / docker container ls が明示されています。旧来の docker run / docker ps も同系統です。

ポイント:

  • イメージ（雛形）とコンテナ（実行インスタンス）
  • ポート公開 -p ホスト:コンテナ
  • データはコンテナ層に書くと消えやすい → ボリューム設計

ルートレスやオーケストレーション（Kubernetes）はレベル1の入口を越えるため、ここでは「次の学習」として触れないで十分です。

6. 現場での見分けと注意

systemd-detect-virt
cat /proc/1/cgroup | head
lscpu
free -h

注意:

  • ネスト仮想化の有無（学習用 VM の中でさらに KVM）
  • コンテナから見た / はホスト全体ではない
  • 特権コンテナは隔離を大きく弱める

7. 現場チェック

  • [ ] ホスト型とハイパーバイザー型を説明できる
  • [ ] VM とコンテナのカーネル共有の違いを言える
  • [ ] systemd-detect-virt / lscpu で仮想化の手がかりを見られる
  • [ ] docker container run と ls ができる
  • [ ] 揮発性ストレージの意味をクラウド文脈で言える

手元で alpine または nginx コンテナを起動し、ポートフォワードでページを一度見てください。可能なら virsh list も。
