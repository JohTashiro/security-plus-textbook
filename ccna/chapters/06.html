06 ルーティング

Cisco 固有の付いた部分は、Cisco 機器だけの書き方や機能名です。他社製品やクラウドでも通じる考え方を優先し、ここは「Cisco ではこう書く・こう呼ぶ」と押さえれば十分です。

異なるサブネット間の通信はルータ（または L3 スイッチ）が転送します。この章では経路表の読み方、静的ルート、シングルエリア OSPF、FHRP（HSRP／VRRP）を、設定と切り分けの単位で押さえます。

1. 経路表の読み方

ルータは宛先 IP に対し「どこへ出すか」を経路表で決めます。

要素 意味
コード 経路の出どころ（C Connected、S Static、O OSPF など）
Prefix / Mask 宛先ネットワーク
Next hop 次に渡す隣接アドレス（または出インタフェース）
AD（Administrative Distance） 経路情報源の信頼度。小さいほど優先
Metric 同一情報源内の「コスト」。小さいほど良いことが多い
Gateway of last resort デフォルトルート（0.0.0.0/0）の行き先 
show ip route
show ipv6 route

出力例の読み方（概念）:

S*  0.0.0.0/0 [1/0] via 203.0.113.1
O   10.10.0.0/24 [110/20] via 10.0.0.2, 00:01:23, GigabitEthernet0/1
C   10.0.0.0/30 is directly connected, GigabitEthernet0/1

S* の * は候補のデフォルト、[AD/metric] が角括弧です。

2. 転送の決め方

デフォルトの優先順の考え方:

  1. 最長一致（Longest prefix match） — /24 より /28 が勝つ
  2. プレフィックス長が同じなら AD が小さい 情報源
  3. AD も同じなら metric が小さい 方（プロトコル依存）

接続済み（Connected）は通常 AD が最も小さく、実務でも「直接つながっている網」が最優先です。

3. 静的ルーティング

IPv4

ip route 10.20.0.0 255.255.255.0 192.0.2.1
ip route 0.0.0.0 0.0.0.0 203.0.113.1
ip route 10.30.0.5 255.255.255.255 192.0.2.1
ip route 10.40.0.0 255.255.255.0 192.0.2.2 210
種類 例
Network route 網全体（例: /24）
Host route /32（特定ホスト）
Default route 0.0.0.0/0
Floating static AD を大きくし、主経路ダウン時の予備

IPv6

ipv6 unicast-routing
ipv6 route 2001:db8:20::/64 2001:db8:1::1
ipv6 route ::/0 2001:db8:1::1

v2.0 では静的の トラブルシュート が明示されています（「v2.0で特に重視」）。ネクストホップ到達性、出インタフェース up、マスク誤り、フローティングの AD を疑います。

確認:

show ip route static
show ipv6 route static
ping / traceroute

4. シングルエリア OSPF

同一エリア（多くは area 0）内でリンクステートを交換し、最短パスを計算します。

OSPFv2（IPv4）

router ospf 1
 router-id 1.1.1.1
 network 10.0.0.0 0.0.0.255 area 0
!
interface GigabitEthernet0/1
 ip ospf 1 area 0
項目 要点
Router ID ルータの識別子。安定した Loopback 由来が多い
Neighbor 隣接関係。Hello などで確立
Point-to-point 対向1台。DR/BDR 不要
Broadcast（Ethernet など） DR/BDR を選出 
show ip ospf neighbor
show ip ospf interface
show ip route ospf

隣接できない典型原因: エリア不一致、サブネット不一致、Hello/Dead 不一致、パッシブ、ACL、インタフェース down。

OSPFv3（IPv6）（v2.0で特に重視）

IPv6 向けの OSPF です。インタフェースにプロセスを載せる形が一般的です。

ipv6 unicast-routing
ipv6 router ospf 1
 router-id 1.1.1.1
interface GigabitEthernet0/1
 ipv6 ospf 1 area 0

show ipv6 ospf neighbor
show ipv6 route ospf

v2.0 の公式範囲ではネイバー隣接の 認証は除外 と明記されています。認証設定そのものより、隣接と経路学習を優先して学びます。

5. FHRP（ファーストホップ冗長）

端末のデフォルトゲートウェイは通常1つです。ルータが落ちると通信が止まるため、仮想 IP を複数ルータで共有します。

プロトコル 位置づけ
HSRP Cisco 系で長年使われる汎用・標準では：標準は VRRP（考え方は同じ）
VRRP 標準ベース。v2.0 で明示（「v2.0で特に重視」）

見るポイント:

  • Active / Master（転送側）と Standby / Backup
  • 仮想 IP が端末の GW と一致しているか
  • 優先度と preempt（切り戻り）
show standby
show vrrp

障害時は「仮想 IP へ ARP できるか」「誰が Active か」を確認します。

6. 切り分けの型

  1. show ip route で宛先の最長一致とネクストホップ
  2. ネクストホップへ ping（自分の出インタフェース／隣接）
  3. 静的ならマスク・AD・書き込み忘れ
  4. OSPF なら neighbor → interface → route
  5. 端末不通なら GW（FHRP 仮想 IP）と ARP

ラボでは、2 台ルータ＋1 台スイッチで静的と OSPF を切り替え、フローティング静的の切り替わりを見ると理解が速いです。

7. 現場チェック

  • [ ] 経路表の AD と metric、最長一致を説明できる
  • [ ] デフォルト／ホスト／フローティング静的を設定・確認できる
  • [ ] OSPFv2 の neighbor が Full になる条件を列挙できる
  • [ ] OSPFv3 をインタフェースに載せる流れを説明できる
  • [ ] HSRP／VRRP の仮想 IP が端末 GW になる理由を言える

確認コマンド例:

show ip route
show ip ospf neighbor
show ipv6 ospf neighbor
show standby brief
show vrrp brief
