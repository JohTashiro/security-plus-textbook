04 スイッチング VLAN STP

Cisco 固有の付いた部分は、Cisco 機器だけの書き方や機能名です。他社製品やクラウドでも通じる考え方を優先し、ここは「Cisco ではこう書く・こう呼ぶ」と押さえれば十分です。

同一物理スイッチでも、VLAN で論理セグメントを分けるのが現行キャンパスの基本です。この章ではアクセス／トランク、EtherChannel（LACP）、Rapid PVST+ とガード機能を、設定と切り分けの単位で押さえます。

1. VLAN の考え方

VLAN はブロードキャストドメインを論理分割します。同一 VLAN 内は L2 で届き、別 VLAN 同士はルータまたは L3 スイッチ（SVI など）経由で通信します。

項目 実務ポイント
通常範囲 1〜1005（現場でよく使うのは 2〜1001 付近）
デフォルト VLAN 多くの環境で VLAN 1。管理・未割当ポートの受け皿になりやすい
アクセスポート 端末用。1 つの VLAN に属する
InterVLAN 別 VLAN 間通信。ルーティング（ルータ on a stick / SVI）が必要 
vlan 10
 name SALES
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10

確認:

show vlan brief
show interfaces status
show interfaces GigabitEthernet0/1 switchport

2. トランクと 802.1Q

スイッチ間やスイッチ−ルータ間で複数 VLAN を運ぶのがトランクです。タグ方式の主流は 802.1Q。

用語 意味
タグ付きフレーム VLAN ID を載せたフレーム
Native VLAN タグなしで運ぶ VLAN。両端で一致させる
DTP トランク交渉。現場では switchport mode trunk 固定が多い汎用・標準では：標準の自動交渉はない。両端を trunk に固定するのが汎用的なやり方 
interface GigabitEthernet0/24
 switchport trunk encapsulation dot1q   ! 機種による
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,30,99

Native VLAN 不一致は「一見つながるが特定 VLAN だけおかしい」原因になります。v2.0 でもトランク／アクセス属性の設定検証は中核です。

確認:

show interfaces trunk
show interfaces GigabitEthernet0/24 switchport

3. EtherChannel（LACP）

複数の物理リンクを 1 本の論理リンク（port-channel）に束ね、帯域と冗長を得ます。CCNA 範囲では LACP が中心です。

前提（両端で揃える）:

  • 速度・二重化
  • スイッチポートモード（access / trunk）と VLAN／トランク設定
  • LACP モード（active / passive など）
interface range GigabitEthernet0/1-2
 channel-group 1 mode active
interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20

確認:

show etherchannel summary
show lacp neighbor

片側だけ設定が違うと、メンバーが独立リンクのまま動いたり、ループや負荷偏りが起きたりします。束ねる前に単独リンクで正常なことを確認する癖が効きます。

4. Rapid PVST+（スパニングツリー）

汎用・標準では：標準は RSTP（IEEE 802.1w）と MSTP（802.1s）。ルートブリッジやポート役割の考え方は共通

冗長リンクがあると L2 ループが起き得ます。STP / Rapid PVST+ はループを防ぎつつ、障害時に代替パスへ切り替えます。Cisco キャンパスでは Rapid PVST+（VLAN ごと）を理解するのが実務・試験の両方で重要です。

役割と状態

役割 意味
Root bridge 木の根。Bridge ID（優先度＋MAC）が最良
Root port 非ルートスイッチがルート方向へ出すポート
Designated port そのセグメントで転送側になるポート
Alternate / Backup ブロック側（待機）
状態（概要） 意味
Discarding 転送しない（Blocking 相当）
Learning MAC 学習中
Forwarding 転送中 
spanning-tree mode rapid-pvst
spanning-tree vlan 10 root primary
spanning-tree vlan 10 root secondary
show spanning-tree vlan 10
show spanning-tree summary

エッジとガード（v2.0 で特に重視）

端末接続ポートでは PortFast（即 Forwarding）を使い、BPDU が来る想定外の接続から守るのが定石です。

機能 用途
PortFast アクセス（エッジ）ポートの高速遷移汎用・標準では：標準の呼び方はエッジポート（RSTP の edge port）
BPDU Guard PortFast ポートで BPDU を受けたら err-disable汎用・標準では：他社にも同じ働きの機能があり、名前が違う（BPDU protection など）
Root Guard 下流から「より良い」BPDU が来てもルートを奪われないようにする
Loop Guard 片方向障害などで代替ポートが誤って転送するのを防ぐ
BPDU Filter BPDU 送受信を抑止。誤用するとループ要因になり得る 
interface GigabitEthernet0/10
 spanning-tree portfast
 spanning-tree bpduguard enable

v1.1 でもガード群は出ますが、v2.0 では Rapid PVST+ の設定・動作とガードの組み合わせがより明示的です。BPDU Filter は「なぜ使うか」を説明できないなら触らない、が現場の安全側です。

5. 切り分けの型

  1. show vlan brief / show interfaces status でポートの VLAN とリンク
  2. トランクなら show interfaces trunk で allowed / native
  3. 冗長経路なら show spanning-tree で root / ブロック
  4. バンドルなら show etherchannel summary でメンバー状態
  5. 端末だけ不通なら、アクセス VLAN とゲートウェイ（SVI／ルータ）を疑う

ラボでは、2 台のスイッチを二重接続し、片側を抜いて STP の再計算を見るのが最短の体感です。

6. 現場チェック

  • [ ] アクセスとトランクの違いを、タグの有無で説明できる
  • [ ] Native VLAN を両端で一致させる理由を言える
  • [ ] LACP で束ねる前に揃える条件を列挙できる
  • [ ] Root / Root port / Designated / ブロックの関係を図にできる
  • [ ] 端末ポートに PortFast + BPDU Guard を付ける理由を説明できる

確認コマンド例:

show vlan brief
show interfaces trunk
show etherchannel summary
show spanning-tree vlan 10
show spanning-tree interface GigabitEthernet0/10 detail
