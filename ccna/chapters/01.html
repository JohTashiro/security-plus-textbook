01 ネットワーク機器と構成

ネットワークは「誰が・どの役割で・どうつながっているか」を把握できないと、設定も障害切り分けも始まりません。この章では機器の役割、よくある構成（トポロジ）、仮想化の考え方を押さえます。

1. 機器の役割

ルータ（Router）

異なる IP ネットワーク同士をつなぎ、経路表に従ってパケットを転送します。境界（社内とインターネット、拠点間）に置くことが多く、NAT や ACL もここで扱う場面が増えます。

レイヤ2スイッチ / レイヤ3スイッチ

  • L2 スイッチ: MAC アドレスに基づき同一ブロードキャストドメイン内でフレームを転送する。VLAN で論理分割できる。
  • L3 スイッチ: スイッチングに加え、VLAN 間ルーティングなど IP 転送も行う。アクセスとディストリビューションの境界でよく使う。

次世代ファイアウォール（NGFW）と IPS

  • ファイアウォール: 許可／拒否のポリシーで通信を制御する。
  • IPS: 攻撃らしき通信パターンを検知・遮断する。
  • NGFW: ポート番号だけでなくアプリケーション識別や脅威情報を組み合わせる製品カテゴリ。設計では「境界で何を見ているか」を文書化する。

アクセスポイント（AP）とコントローラ

AP は無線クライアントを有線 LAN に橋渡しします。コントローラ（WLC やクラウド管理）は複数 AP の設定・認証・電波ポリシーを集中管理します。小規模では AP 単独（自律型）、中大規模ではコントローラ型が一般的です。

エンドポイントとサーバ

PC・スマホ・プリンタなどの端末と、サービスを提供するサーバです。設計・障害時は「端末側の NIC／IP」と「サーバ側の待ち受け」を分けて疑います。

PoE（Power over Ethernet）

LAN ケーブル経由で AP・IP 電話・カメラなどに給電します。スイッチの PoE 予算（ワット合計）とケーブル品質を超えると、端末が起動しなくなる・再起動を繰り返す、といった症状になります。

2. よくあるトポロジ

構成 特徴 使いどころ
Two-tier（折りたたみコア） アクセス＋ディストリ／コア 中小キャンパス
Three-tier アクセス／ディストリ／コア 大規模・階層分離したいとき
Spine-leaf leaf が端末やサーバ、spine が葉同士をつなぐ データセンター
WAN 拠点間を専用線・VPN 等で接続 多拠点
SOHO ルータ一体型＋少数端末 在宅・小規模店舗
On-premises / Cloud 自社設置かクラウド上か ハイブリッド設計の前提

現場では「どの階層に障害が出たか」で影響範囲が変わります。アクセス障害は局所、コア障害は全体に広がります。

3. 仮想化の基礎

  • サーバ仮想化: 1台の物理サーバ上で複数 VM を動かす。ハイパーバイザが CPU・メモリ・NIC を割り当てる。
  • コンテナ: OS カーネルを共有し、プロセス単位で隔離する。起動が軽く、アプリ配布に向く。
  • VRF: ルータ／L3 スイッチ上で経路表を論理分割する。同じ機器でもテナントや用途ごとにルートを分ける。

v2.0 ではハイパーバイザ・VM・コンテナの関係を説明できることが特に重視されます。試験対策というより、「物理 NIC の向こうに仮想スイッチがある」ことをイメージできるかが実務でも効きます。

4. スイッチング概念の入口

L2 スイッチは送信元 MAC を学習し、宛先 MAC がテーブルにあればそのポートへ転送、なければフラッディングします。詳細（エージング、VLAN、STP）は第04章で扱います。ここでは「MAC テーブルが壊れる／満杯／不整合だと通信がおかしく見える」と覚えてください。

5. 現場チェック

  • [ ] 自社（または自宅ラボ）の機器を、上の役割名で言い換えられる
  • [ ] 構成図を Two-tier / Three-tier / Spine-leaf のどれに近いか説明できる
  • [ ] VM とコンテナの違いを、隔離の単位で説明できる
  • [ ] PoE 機器が増えたとき、スイッチの給電上限を確認する癖がある

show version
show ip interface brief
show mac address-table
show power inline
