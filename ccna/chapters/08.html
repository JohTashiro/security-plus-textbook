08 セキュリティ基礎

接続とサービスが動いても、不正アクセスやなりすましを防げなければ本番は成立しません。この章では脅威の用語、機器の管理アクセス、ACL、レイヤ2セキュリティ、AAA、IPsec VPN の概要を実務単位で押さえます。

1. 脅威・脆弱性・エクスプロイト・緩和

用語 意味のイメージ
Threat（脅威） 害を与えうる主体や状況
Vulnerability（脆弱性） 攻撃に使われうる弱点
Exploit（エクスプロイト） 脆弱性を突く手法・コード
Mitigation（緩和） リスクを下げる対策

現場では「完全排除」より、露出を減らし検知・復旧まで含めた緩和が中心です。

セキュリティプログラムの要素として、ユーザ意識向上・訓練・物理アクセス制御も忘れないでください。強いパスワードでも、カードキー無しのサーバルームや USB の持ち込み放置は別の穴になります。

2. 管理アクセスとパスワード方針

機器へのログイン経路はコンソール、SSH（推奨）、（非推奨の）Telnet、HTTPS の GUI、クラウド管理などがあります。

username admin privilege 15 secret ComplexP@ss1
line vty 0 4
 login local
 transport input ssh

パスワード方針の観点:

要素 現場での意味
管理 誰が発行・失効するか
複雑性 長さ・文字種・辞書回避
代替 MFA、証明書、生体など

ローカルユーザだけでは規模に限界があるため、次節の AAA と組み合わせます。v2.0 では ローカルユーザ名と AAA クライアント（TACACS+/RADIUS）としての管理設定 が明示されています（「v2.0で特に重視」）。

3. AAA（認証・認可・アカウンティング）

文字 意味 例
Authentication 誰か ユーザ／パス、証明書
Authorization 何をしてよいか privilege、コマンド許可
Accounting 何をしたか ログイン時刻、コマンド記録

TACACS+ は機器管理でよく使われ、RADIUS は無線・VPN のユーザ認証でも多い、という役割分担の感覚で十分です。機器側は「AAA クライアント」、サーバ側が認証基盤です。

4. ACL（アクセス制御リスト）

パケットを許可／拒否するフィルタです。インタフェースの in / out 方向と、照合順序（上から最初の一致）が要点です。

種類 典型
標準 ACL 送信元 IP 中心。番号 1–99 など
拡張 ACL 送信元・宛先・プロトコル・ポート
番号付き / 名前付き 管理しやすさの違い 
ip access-list extended BLOCK_SSH_FROM_GUEST
 deny tcp 10.99.0.0 0.0.0.255 any eq 22
 permit ip any any
interface GigabitEthernet0/1
 ip access-group BLOCK_SSH_FROM_GUEST in

暗黙の deny any があること、permit ip any any を最後に置く意図、どこに適用するかを説明できるようにしてください。v2.0 は 標準／拡張／番号付き／名前付き の設定が明示されています。

5. レイヤ2セキュリティ

機能 狙い
Port security 許可 MAC 以外を制限
DHCP snooping 正規 DHCP サーバ以外の応答を抑止
Dynamic ARP Inspection（DAI） 不正 ARP を抑止（snooping DB と連携）
Storm control ブロードキャスト等の嵐を抑制（v2.0で明示）
RA guard 不正な IPv6 RA を抑制（v2.0で明示） 
interface GigabitEthernet1/0/10
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security violation restrict

DHCP snooping では 信頼ポート（アップリンク／サーバ側） と非信頼ポートの切り分けが典型のつまずきです。v2.0 の L2 セキュリティ一覧に storm control / RA guard が加わります（「v2.0で特に重視」）。

6. IPsec VPN 概要

形態 イメージ
Site-to-site 拠点間を常時接続
Remote access ノート PC 等から都度接続

プロトコルとモード（トンネル／トランスポート）の名前と用途の対応ができれば CCNA の説明範囲としては足場になります。詳細な暗号スイート暗記より、「何を守り、どこで終端するか」を優先します。v2.0 は プロトコルとトランスポートモード まで言及しています。

無線の WPA／WPA2／WPA3 は第05章と重複します。ここでは「PSK とエンタープライズ（802.1X）の違い」「WPA3 が現行推奨寄り」程度の復習で十分です。

7. 設定ファイルの安全な転送（運用接点）

バックアップや IOS イメージの受け渡しは、平文 TFTP より SFTP / SCP が推奨です。v2.0 で明示（「v2.0で特に重視」）。セキュリティ章の延長として、「管理プレーンの通信も暗号化」と覚えてください。

8. 現場チェック

  • [ ] 脅威／脆弱性／エクスプロイト／緩和を自分の言葉で区別できる
  • [ ] VTY を SSH のみ・ローカルユーザで固める流れを説明できる
  • [ ] AAA の3要素を業務例で言える
  • [ ] 標準と拡張 ACL の違いと、適用方向の意味を説明できる
  • [ ] ポートセキュリティと DHCP snooping の目的を言える
  • [ ] site-to-site と remote access の違いを説明できる

ラボ例:

  • 拡張 ACL で特定サブネットから SSH を拒否し、他通信は通す
  • アクセスポートに port-security maximum 1 を入れ、別 PC 接続時の violation を観察
