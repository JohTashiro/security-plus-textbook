02 ケーブルとインタフェース障害

リンクが上がらない、速度が遅い、エラーが増える——現場で最初に疑うのは論理設定より物理とインタフェース状態です。この章では媒体の種類、二重化／速度、切り分け手順を押さえます。

1. ケーブルの種類

銅線（Copper）

UTP / STP の Ethernet ケーブルが中心です。カテゴリ（Cat5e / Cat6 など）と長さ制限（おおむね 100m）を超えると、リンク不安定や誤りが増えます。ストレートとクロスの区別は、現行の Auto-MDIX 付き機器では意識しにくいですが、古い機器や特殊ポートではまだ効きます。

光ファイバ

種類 特徴 使いどころ
マルチモード（MMF） コアが太い。短〜中距離 ラック間・フロア間
シングルモード（SMF） コアが細い。長距離 キャンパス間・WAN 寄り

光は送受信（Tx/Rx）の向きとコネクタ種別（LC など）、モジュール（SFP/SFP+）の互換が重要です。銅線用ポートに光モジュールを挿しても動きません。

接続の形態

  • 共有メディア: 昔のハブ的な衝突領域の考え方。現行スイッチではポートごとに独立した衝突ドメイン。
  • ポイントツーポイント: ルータ間や光リンクなど、1対1接続。

2. 速度と二重化（Duplex）

項目 内容
速度 10/100/1000 Mbps など。両端で一致させる
全二重（full） 送受信同時。スイッチ接続の標準
半二重（half） 同時送受信しない。衝突（collision）が発生し得る

一方が auto、他方が固定、あるいは片方が half 固定だと mismatch duplex になり、遅い・切れやすい・CRC/collision が増える典型パターンです。v2.0 ではケーブル診断（距離、信号レベル、pin out、タイプ）や duplex 不一致の切り分けがより明示的に問われます。

3. よくある症状と見るカウンタ

Cisco IOS 系での確認例:

show interfaces GigabitEthernet0/1
show interfaces status
show interfaces GigabitEthernet0/1 counters errors

見るポイント:

  • line protocol is down / administratively down: ケーブル・対向電源・shutdown
  • CRC / input errors: ケーブル不良、ノイズ、二重化不一致
  • collisions / late collisions: 半二重や距離・配線の問題を疑う
  • runts / giants: フレーム長異常。二重化や不良も関連し得る
  • speed / duplex: show interfaces status で実効値を確認

光リンクでは、光モジュールの有無、Tx/Rx の入れ違い、汚れ、対応波長も疑います。

4. 切り分けの順番（実務）

  1. LED / show interfaces status でリンクの有無
  2. ケーブル交換・別ポート・別パッチ盤で切り分け
  3. 両端の speed/duplex（auto 同士が基本。固定するなら両端そろえる）
  4. エラーカウンタをクリアして再計測（一時スパイクか継続か）
  5. それでもダメなら SFP／対向機器／配線経路へ

ラボで再現するなら、わざと片側だけ 100/full 固定にして症状を観察すると理解が速いです。
