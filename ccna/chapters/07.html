07 IP サービス

経路が通っても、アドレス・名前・時刻・ログが崩れると運用は止まります。この章では DHCP、DNS、NAT、NTP、syslog、SNMP、QoS 概要を実務単位で押さえます。

1. DHCP の役割

端末に IP・マスク・ゲートウェイ・DNS などを自動配布します。

役割 内容
DHCP サーバ プールからリース
DHCP クライアント 要求して受け取る
DHCP リレー 別サブネットのサーバへ転送（ヘルパー）

ルータをクライアントにする例と、リレーの概念:

interface GigabitEthernet0/0
 ip address dhcp
!
interface GigabitEthernet0/1
 ip helper-address 192.0.2.10

切り分け: 端末が APIPA（169.254）ばかり → サーバ到達性、リレー、VLAN、プール枯渇、snooping の信頼ポート設定を疑う。

v2.0 では DHCPv4 の client / server / relay のトラブルシュート が明示されています（「v2.0で特に重視」）。

2. DNS の役割

名前を IP に（または逆に）解決します。アプリ障害の多くは「名前が解けない」です。

レコード 用途の例
A ホスト名 → IPv4
AAAA ホスト名 → IPv6
CNAME 別名
MX メール配送先
NS ゾーンの権威サーバ
PTR IP → 名前（逆引き）

v2.0 ではこれらレコードの 診断 が明示されています（「v2.0で特に重視」）。クライアントでは nslookup / dig、到達性は DNS サーバへの UDP/53（または DoT 等は範囲外の理解で可）を確認します。

3. NAT / PAT

プライベートアドレスをインターネット側で使えるアドレスに変換します。

種類 イメージ
Static NAT 1対1 固定
Dynamic NAT（プール） プールから動的割当
PAT（オーバーロード） 多数対1。ポートで識別。最も多い 
access-list 1 permit 10.0.0.0 0.0.0.255
ip nat inside source list 1 interface GigabitEthernet0/0 overload
interface GigabitEthernet0/1
 ip nat inside
interface GigabitEthernet0/0
 ip nat outside

show ip nat translations
show ip nat statistics

v2.0 は IOS XE での NAT/PAT を明示（「v2.0で特に重視」）。inside/outside の付け間違いと ACL の取りこぼしが典型障害です。

4. NTP

時刻ずれは証明書・ログ相関・認証を壊します。

ntp server 192.0.2.53
ntp master 3          # ラボ用のサーバ役など
show ntp status
show ntp associations

クライアントが上位を参照する構成が基本です。本番は信頼できる時刻源へ。

5. syslog と SNMP

syslog

機器のイベントをメッセージとして送ります。

要素 意味
Facility メッセージの分類
Severity 0 Emergency 〜 7 Debugging の重大度

数値が小さいほど深刻、という感覚で十分です。遠隔サーバへ送る設定と、バッファ／コンソールのレベルを現場では揃えます。

v2.0 ではメッセージ内容・severity・ファシリティの 解釈 が明示されています。

SNMP

監視サーバが機器の状態を取得／（設定によっては）変更する枠組みです。運用では「何を監視しているか」「コミュニティ／ユーザの扱い」が要点です。詳細な MIB 暗記より、役割の説明ができれば CCNA としては足場になります。

6. QoS 概要（PHB）

混雑時に「誰を先に通すか」を決める考え方です。

用語 意味のイメージ
Classification 分類（どのトラフィックか）
Marking DSCP 等で印を付ける
Queuing 待ち行列
Congestion 輻輳への対処
Policing 超過を落とす／マーク
Shaping 超過を遅らせて平滑化

音声は低遅延、バックアップは遅延許容、といった設計意図を言葉にできれば十分です。詳細キューイングの暗記より、用語の対応を優先します。

7. 現場チェック

  • [ ] DHCP サーバ／クライアント／リレーの役割を説明できる
  • [ ] A / AAAA / CNAME / MX / NS / PTR の用途を言える
  • [ ] PAT が「多数の内部→少ないグローバル」である理由を説明できる
  • [ ] NTP ずれの影響を業務例で言える
  • [ ] syslog の severity の大小感覚と SNMP の役割を説明できる

ラボ例:

  • ルータを DHCP リレーにし、別網のサーバからアドレスが付くことを確認
  • PAT 前後で show ip nat translations を見る
