05 無線 LAN

有線の L2 が整っても、端末の多くは無線で入ります。この章では RF の感覚、SSID／セキュリティ、AP と WLC の役割、チャネル設計を、設定と切り分けの単位で押さえます。

1. 無線の原則（RF）

無線は電波で届きます。有線と違い、障害物・干渉・距離が品質を左右します。

用語 実務ポイント
RF（Radio Frequency） 電波そのもの。減衰・反射・干渉を意識する
バンド 主に 2.4 GHz と 5 GHz（環境により 6 GHz も）
チャネル 帯域内の区分。隣接チャネル干渉を避ける
SSID ネットワーク名。端末が選ぶ「見える名前」
RSSI / SNR 受信強度とノイズ比。弱い・汚い電波は切れやすい

2.4 GHz は壁を抜けやすいが混雑しやすい。5 GHz は帯域が広く高速向きだが、障害物に弱いことが多い、というのが現場の出発点です。

非重複チャネル

2.4 GHz では 1 / 6 / 11 が非重複の定番です。隣同士（例: 1 と 2）は干渉しやすいので、オフィスではこの3つでセルを組むことがほとんどです。

v2.0 ではバンド／チャネル選択、干渉要因、セキュリティパラメータの切り分けがより明示的です（「v2.0で特に重視」）。

2. SSID とセキュリティ

SSID は WLAN の論理名です。同じ SSID を複数 AP に載せてローミングさせるのが一般的です。

方式 イメージ
オープン 認証なし。ゲスト検証用以外では使わない
WPA2-PSK 事前共有鍵。中小・SOHO で多い
WPA2 / WPA3 Enterprise 802.1X＋RADIUS。企業の定番
WPA3 より強い鍵交換。端末対応を確認して導入

CCNA 範囲では WPA / WPA2 / WPA3 の位置づけと、GUI で WPA2-PSK の WLAN を作れることが中心です。鍵は長くランダムに。SSID を隠してもセキュリティにはなりません。

クライアント側の失敗例:

  • 間違った PSK
  • 企業認証なのに個人用プロファイルで接続
  • バンド固定や古いドライバで 5 GHz に乗れない

3. AP と WLC（アーキテクチャ）

形態 特徴
スタンドアロン AP AP 単体で設定。小規模向き
コントローラベース（WLC） AP を集中管理。SSID・セキュリティ・RF を一括

エンタープライズでは Lightweight AP + WLC が主流です。AP は有線スイッチに接続し、管理用のトンネルで WLC とやり取りします（CAPWAP の概念で十分）。

物理接続の型:

  • AP のアップリンクは多くの場合 アクセスポート（特定 VLAN）または トランク（複数 SSID＝複数 VLAN）
  • WLC はスイッチへ接続。複数リンクを束ねる LAG も出る
  • 端末 VLAN と管理 VLAN を分け、有線側の VLAN／トランク設計と揃える

AP モード（概要）:

  • Local（通常）: クライアント接続を処理
  • Monitor / Sniffer 系: 監視・調査寄り（詳細名は機種依存）
  • 現場では「どの AP がクライアントを載せるか」を WLC／GUI で確認する

4. WLAN の GUI 設定で見るポイント

WLC（または同等の管理画面）で WLAN を作るとき、最低限そろえる項目です。

  1. WLAN / SSID 名と有効化
  2. セキュリティ（例: WPA2-PSK、鍵）
  3. インターフェース／VLAN の対応
  4. QoS プロファイル（音声など優先が必要な場合）
  5. 詳細設定（ブロードキャスト SSID、クライアント制限など）

確認の型:

  • AP が WLC に Join しているか
  • WLAN が Enabled か
  • クライアント一覧に端末が出るか、拒否理由はないか
  • 有線側でその VLAN のゲートウェイへ届くか

5. チャネル設計と干渉

要因 例
同一チャネル干渉 隣の AP が同じチャネル
隣接チャネル干渉 2.4 GHz で 1 と 2 など
非 Wi-Fi 干渉 電子レンジ、コードレス電話、Bluetooth（特に 2.4）
障害物 金属ラック、コンクリート、人体

対策の基本は「非重複チャネル」「適切な送信出力」「AP 密度の見直し」です。出力を上げすぎるとセルが重なり干渉が増えます。

6. クライアント接続の切り分け

有線と共通の層に、無線固有の層が乗ります。

  1. 端末が正しい SSID を選んでいるか（セキュリティ方式一致）
  2. 認証・鍵は通っているか（PSK／802.1X）
  3. DHCP で IP が付いたか（有線 VLAN 問題と共通）
  4. ゲートウェイ・DNS へ届くか（ping / ブラウザ）
  5. RF: 別 AP・別バンド・近い場所で再現するか

v2.0 では Windows / macOS / Linux 上の IP 設定・到達性・無線セキュリティパラメータのトラブルシュートが明示されています。端末の「接続済みだがインターネットなし」は、まず IP／GW／DNS を疑うのが定石です。

7. 現場チェック

  • [ ] 2.4 GHz の非重複チャネル（1/6/11）を説明できる
  • [ ] SSID と WPA2-PSK／Enterprise の使い分けを言える
  • [ ] スタンドアロン AP と WLC 管理の違いを説明できる
  • [ ] AP の有線接続（アクセス／トランク）と VLAN の関係を図にできる
  • [ ] 「電波は届くが IP が付かない」とき、無線と有線のどちらを疑うか順序立てられる

ラボ例:

  • Packet Tracer / 実機で SSID＋WPA2-PSK を作り、端末接続を確認する
  • 有線側 VLAN をわざとずらして「認証は通るが通信できない」を再現する
