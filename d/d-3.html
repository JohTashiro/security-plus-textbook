特定（スキャン・アプリ）

脆弱性スキャンVulnerability scan

システム／網の既知弱点を洗い出す

代表例
  • ポート・版チェック
  • SQLインジェクション／XSS検査

アプリの静的な分析Static analysis

アプリを動かさずコードを解析する

代表例
  • SASTツール
  • 入力連結の検出

アプリの動的な分析Dynamic analysis

アプリを動かしながら挙動を分析する

代表例
  • DAST
  • 実行時のXSS確認

パッケージモニタリングPackage monitoring

依存パッケージの既知脆弱性を監視する

代表例
  • OSSライブラリ監視
  • 安全な版への更新

特定（脅威フィード）

OSINTOpen-source intelligence (OSINT)

公開情報から脅威・脆弱性を把握する

代表例
  • SNSの製品情報
  • コミュニティの攻撃手法

第三者（独自／サードパーティ）Proprietary / third-party

外部ベンダーの脅威フィードを使う

代表例
  • 有料インテリジェンス
  • ゼロデイ情報の購読

情報共有組織Information-sharing organization

業界等で脅威情報を共有する組織

代表例
  • ISAC
  • 金融機関同士の共有

ダークウェブDark web

匿名空間から攻撃・漏洩情報を得る

代表例
  • Tor上のフォーラム
  • 認証情報売買の監視

特定（テスト・監査）

侵入テストPenetration testing

許可下で攻撃者視点の実効性を試す

代表例
  • 入力フォームへの不正データ
  • 依頼ベースの評価

バグバウンティプログラムBug bounty program

外部発見に報奨金を出す制度

代表例
  • ホワイトハッカーへの報酬
  • 報告の検証と支払い

システムやプロセスの監視（監査）System/process audit

方針・規制への準拠を評価する

代表例
  • セキュリティ監査
  • ポリシー遵守の点検

分析

偽陽性False positive

問題ないのにありと誤判定する

代表例
  • スキャナの誤検知
  • 手動検証で否定

偽陰性False negative

問題があるのになしと見逃す

代表例
  • 監査で見落とし
  • 後日の侵害で発覚

優先順位付けPrioritize

影響に基づき修正順を決める

代表例
  • 中核機能の脆弱性を先に
  • 低影響は後回し

CVSSCommon Vulnerability Scoring System (CVSS)

深刻度を0〜10で示す基準

代表例
  • 特性の採点
  • 優先度の定量根拠

CVECommon Vulnerabilities and Exposures (CVE)

脆弱性に一意IDを付ける仕組み

代表例
  • CVE-年-番号
  • ExchangeのCVE例

脆弱性の分類Vulnerability classification

特徴で脆弱性をグループ化する

代表例
  • OWASP Top 10
  • インジェクション等の類型

環境変数Environmental variables

環境上の設定／要因を分析に織り込む

代表例
  • DB接続情報の保管
  • 環境要因と優先度

リスク許容度Risk tolerance

組織が受け入れられるリスク水準

代表例
  • 決済情報扱い＝許容低
  • 対応の厳しさに反映

対応・是正

パッチPatching

ベンダー修正を適用して塞ぐ

代表例
  • 緊急パッチ展開
  • メンテ窓での適用

保険Insurance

損害を保険で金銭補償する

代表例
  • サイバー保険
  • 復旧・賠償のカバー

セグメンテーションSegmentation

網を分割し横展開を抑える

代表例
  • 重要系の分離
  • 最小通信の許可

代替的対策Compensating controls

本来策が不可のとき別手段で抑える

代表例
  • パッチ保留中のIPS
  • 同等効果を目指す制御

例外と免除Exceptions and exemptions

例外＝別対応許可、免除＝対応不要

代表例
  • 代替策付きパッチ延期
  • 隔離ラボの対応免除
